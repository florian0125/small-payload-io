# 媒体与恢复

## 音视频

本地音视频可以远大于 1 MB；决定是否超限的是送入对应工具/请求的表示，而非源文件大小。先字幕、讲义，再离线 ASR，再必要的关键帧。无转写模型时检查已有本地环境，不把云转写当作隐式授权。

已安装 FFmpeg 的使用示例（输出到新文件，`-n` 不覆盖）：

```powershell
& $ffmpeg -nostdin -hide_banner -loglevel error -n -i $video -vn -ac 1 -ar 16000 -c:a pcm_s16le -f segment -segment_time 180 -reset_timestamps 1 "$work\audio-%04d.wav" 2> "$work\ffmpeg.log"
& $ffmpeg -nostdin -hide_banner -loglevel error -n -ss 2400 -i $video -frames:v 1 -vf 'scale=1280:-2' -q:v 7 "$work\frame.jpg" 2> "$work\frame.log"
```

WAV 比有损压缩音频大很正常，因为用于本地转写。按时间分块不保证每个文件低于某个字节限制。若授权的外部接口对单文件有上限，逐块检查实际字节并递归缩短时长，且确认接口支持该媒体类型。

有 `video-local-reader` 时使用其离线模型与 180 秒、3 秒重叠转写流程，保留时间戳、重复边界与识别不确定标记。只把文字交给本 skill 的 `pack/read`；不要初始化不同预算后累积读取。完整转写不是理解完整视频：代码、图表、口误仍需回到时间戳核对。

## 缓存与历史

- 磁盘临时图片、转码片段：删除释放磁盘，不改写已经进入对话的内容。仅在磁盘问题或任务完成时清理本次任务所有的临时文件；先验证绝对路径、所有权与引用关系。原件、进度、账本、授权记录和用户资料不清理。
- 本地转写模型和下载缓存：通常与请求大小无关，删除会导致重下；不作为 1 MB 故障修复。
- 服务端 prompt cache：复用计算，不是本机可删除的对话附件。官方资料说明未提供手动清除机制。
- 对话历史：保存精简进度，使用客户端支持的上下文压缩或精简交接的新任务。当前工具不一定提供压缩能力，不得虚构“已清空”。压缩操作也可能需要发送旧上下文，不能保证挽救已被代理拦住的请求。

官方依据：[Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[App Server](https://learn.chatgpt.com/docs/app-server)。官方存在 `thread/compact/start` 协议不等于当前任务有对应工具；不要另起服务抢改正在运行的任务。

## 错误分流

| 证据 | 行动 |
|---|---|
| 请求体大、413 或明确代理大小通知 | 查原始/压缩后请求字节，减少新增内容；已有大历史时交接新任务。 |
| 一般 403、401 | 先诊断鉴权/权限/代理策略，不用压缩掩盖授权问题。 |
| context length/token 错误 | 选择相关证据、分层笔记、支持的上下文压缩；修改 token 配置不能提高代理字节限制。 |
| 不支持视频/文件格式 | 本地转为受支持的文字/图片；压小不会增加视频理解能力。 |
| 磁盘不足 | 仅清理已验证属于本任务的临时文件，保留进度和原件。 |

不修改企业网关规则，不换未经授权的传输通道，不删除全局 .codex 会话/认证/缓存目录，不自动清空任务历史，不循环重试相同超大请求。
