# 真实 403 → 完成任务的验收（2026-10-23）

用户要求证明解决超限有效时，预先定义具体问题、独立预期答案和接受条件。通过须同时具备：原请求明确为相关代理 403；处理后每个必要请求 HTTP 200 且推理完成；所有必要结果合并后答案一致。不能拿 401、模拟 413、连接错误、只看尺寸或不完整读取替代。

已完成 11 组成对真实请求测试，全部通过。路径为当前网络代理到官方 Codex 推理端点，现有登录身份，合成输入，受控无状态客户端。不是整个桌面代理自动选用 skill 的端到端测试。

一个额外对照保持同一图片与完全相同 JSON：identity 1,801,782 字节返回代理 403，zstd 12,557 字节返回 200，并读对图内码。这说明该链路的传输表示会影响拦截；不证明所有代理只计算传输字节。zstd 前后都超过限制的图片/日志仍会被拦截。skill 本身不能为所有工具强行配置 HTTP 压缩；已启用 zstd 时仍应减少原始内容。

多图一次初始连接中断已保留，随后仅一次同内容重试得到明确 403。所有最终接受结果同时校验了模型答案。任务读者不能因此把通用 403 都归因于大小。

现有脚本已验证的有效步骤：对图片裁切相关区域后 JPEG 压缩；日志按目标 trace 精确筛选；多文件保留全部目标记录再统一拆包；大记录集合投影问题所需字段并逐包读完；最终答案与全部预期结果核对。筛选与压缩都必须以用户的具体阅读目标为依据，不能把少读资料伪装成完整完成。
